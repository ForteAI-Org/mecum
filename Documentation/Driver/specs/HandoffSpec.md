# AgentSeatKit handoff specification

Status: **final**, September 8, 2026. Consolidated from the `map.md` wayfinder (15 closed tickets). Each section points to the supporting research note under `research/`. The implementation plan is in section 12 and in the tickets under `implementation/`. Implementation is intended for Opus 5 High agents, one phase per session, starting from the package stub already in place.

## 1. Objective and boundary

Extract from AgentSeatLab (`Research_locator`) everything that controls the Mac and is agnostic about who makes decisions: virtual display, background input (keyboard, text, click, drag, scroll), cursor fence, seat capture, and orchestration with guards and recovery. The Planner, LLM client, AX observation, and UI remain in the Lab. The migration is also a cleanup: only what works today on the agent path is included; anything marked FAIL or "to be run" belongs in `docs/SpiLedger.md`, not in the code.

Non-negotiable invariants:

- **The kit receives observed coordinates, not trees.** Observation (screen, analysis, representation, model) stays outside; every mouse point arrives with the identity, geometry, and scale that produced it. The kit uses Accessibility only for **window placement**: `AXPosition` to move the window, `AXRaise` to bring it on stage, and `_AXUIElementGetWindow` to find its element (ticket 16). `TargetReader` **reads and returns**: it reduces an AX tree to an array of lightweight value structures, never writes to the target, never performs an action, and never acts as a facility fallback. No facility depends on it, and the caller decides what to do with its result (decision dated 2026-09-09).
- **No cross-seat fallback**: never send a global event to the User Seat. A facility refuses a missing permission, unresolved symbol or invalid layout. Missing build qualification is marked without blocking use (ADR 0015).
- **Never replay an uncertain effect**: a Command whose confirmation is `unknown` is not repeated.
- **The kit does not decide actions**: effect verification, window closure, and scheduling among agents belong to the caller.

## 3. Style

The kit's `CodeStyle.md` and `CLAUDE.md` (already written under `AgentSeatKit/`) derive from `fEditorEngine/CodeStyle.md` and the Reix rules: make `public` explicit and deliberate; name protocols by role (`WindowRelocating`), never with a `Protocol` suffix; place `///` on every type and member with the symbol name as the subject; keep `//` comments to at most two lines; never use em dashes; use the headers `//  File.swift` / `//  AgentSeatKit` / `//  Created by Eliomar Alejandro Rodriguez Ferrer on DD/MM/YYYY.`; align columns, including at call sites; place opening parentheses at the end of a line and closing parentheses on their own line; place property wrappers on their own line; allow at most two top-level types per file; and organize folders by concern with unrestricted subfolders. Names come from the kit's `Context.md` glossary. The Lab has no transitional `typealias`. Errors use one type per facility, English messages, and structured fields. Logging uses `os.Logger` with subsystem `dev.forte.AgentSeatKit` and one category per facility; C `os_signpost` calls use no arguments under the `DynamicTracing` category (the only zero-allocation form, ticket 05).

**No umbrella target (user decision, 2026-09-09).** The `AgentSeatKit` target and its `@_exported import` declarations are removed: each consumer imports the modules it uses, and each target declares everything it imports even when a module would otherwise arrive transitively. This makes a later package split a matter of moving targets and nothing else. There are still two **products**: `AgentSeatKit`, containing the eight targets that conduct a session, and `TargetReader` on its own, because a product is a linking unit, not a module.

**Amendment dated 2026-09-09 (user decision).** The kit ships no application: `AgentSeatFixture` is removed as a target. Test applications (the instrumented fixture with the correct layout, its IPC, `MetalPulseView`, and `AXFocusSentinel`) remain consumer-owned, and the entire backend of their functions calls the kit. The Live tier locates the instrumented target through `AGENTSEAT_FIXTURE_APP`, so the kit names no consumer and skips those rows when the variable is absent. Interpretation also leaves the probe: the caller derives an element's category and actions from its role. **One write remains permitted**, `AXManualAccessibility` on Chromium targets, because it is a precondition for reading rather than an action on the target. Without that switch, an Electron app exposes only a handful of elements and no text (user decision, 2026-09-09).

**Clipboard amendment dated 2026-09-09: closed (user decision).** There is neither a verb nor a module. `InputCommand` remains at **five cases**, and `SeatClipboard` is removed.

The reason is measured, not estimated. A routed Command-V **reaches** both target families and **neither executes it**. The same is true for each of the **eleven paths** tested: the public route; the unstamped private record; the record stamped with window and connection as the mouse path does; the record stamped with Preparation; `AXUIElementPostKeyboardEvent`; `SLEventPostToPid`; Accessibility activation of the Paste menu item; and the contextual menu opened by right click or requested through AX. A keyboard equivalent is resolved by the **application menu**, and that menu belongs to whoever is truly in the foreground, which the seat can never become. The WindowServer accepts the records (always returning 0) and AppKit never resolves them, so **the failure is silent**: no code can distinguish execution from rejection. The detector remains as a Live test built from the two raw events; if a future build executes them, the run fails.

The negative result for contextual menus is broader than expected and also applies to ticket 12: **a background application does not open one at all**, in either family, with or without Preparation.

The module is removed because it has no possible consumer without paste. The path that *does* place text in a background target does not use the clipboard: it **writes the Accessibility value** of the focused element, which takes effect without a single event and with one change notification. It belongs in the consumer, not the kit, because of this specification's invariant: the kit receives coordinates, not trees. It is not universal either. It was verified on one native window and on a browser launched with `--force-renderer-accessibility`, but is **not usable on a framework-based editor**, where the value read back lags by at least one write and therefore cannot be confirmed. Those targets must be typed into, which is what the kit has always known how to do.

The measured facts remain in `docs/SpiLedger.md`, the proper place for a fact without code: the eleven paths and their outcomes, the keyboard-record shape, the `changeCount` race window, and the read of a promised type that raises an exception Swift cannot catch and **kills the reading process**.

## 5. Public API

### SeatHost
`init(configuration: SeatHostConfiguration)` (`refreshRate` defaults to 60; 120 is allowed), `start() async throws`, `stop() async`, `makeSeat() throws -> AgentSeat`, `state: off | starting | ready | degraded | failed`, `events: AsyncStream<SeatEvent>`, `monitor: Monitor`, `displayID`. `start` enables the virtual display and fence as one atomic step: if either fails, the other is dismantled. v1 permits one seat per host and one host in the process; the model permits `n`. Host issues (`displayChanged`, `fenceUnavailable`, pointer on the virtual display) move the host and all seats to `failed`, followed by fail-closed teardown with best-effort window release. `monitorUnavailable` produces `degraded`. The watchdog performs eight checks (main display, physical geometry, virtual display online through `CGGetOnlineDisplayList`, tap active, tap never disabled, pointer outside the virtual display, pointer inside the physical region, and readable position) on events (the tap callback and `CGDisplayRegisterReconfigurationCallback`) plus a 1 s heartbeat. `stop` releases windows, removes the display (waiting at most 2 s), and restores physical origins only if the display set matches the baseline; otherwise it reports `topologyChangedByUser`. (Ticket 10.)

### AgentSeat
`state: unavailable | starting | ready | acting | waiting | recovering | degraded | failed`; `events: AsyncStream<SeatEvent>`.
- **Turn**: `acquire() async throws -> Turn` enters a cancellable FIFO queue. `Turn.generation` is monotonic, and `seatChangedSinceLastHold` indicates a changed generation so the caller observes the seat again. `release(_ turn:) throws` is allowed only when every Command has been confirmed. Leases, epochs, TTLs, priority, and revocation belong to Orchestrator's SeatBroker, built above the Turn.
- **Windows**: `adopt(_ window: WindowReference, platform: any InputPlatform = .universal) async throws -> AdoptedWindow` moves through `AXPosition` and confirms with two WindowServer reads. Every window is either `staged` (full size, one per host) or `stashed` (a Stage Manager thumbnail). `stage(_:)` uses `AXRaise` and two confirmation reads (0.5 s on Chrome, 19 ms on the fixture, with no activation; ticket 16). `release(_ window:, .returnToUserSeat | .leaveOnVirtualDisplay)` releases it; closing windows is outside the kit.
  Adoption also recognizes a thumbnail that remains on the physical display after `AXPosition`: it stages the window before confirming containment, without activating the application. An error or cancellation after the move attempt starts restoration to the original frame, verified by two reads of the same identity. `lastAdoptionFailure` retains the cause, geometry before rollback, and outcome. `hasPendingWindowRestorations` reports an unconfirmed restoration, which blocks the seat and is retried during teardown. The restored window may be stashed on a physical display; in that case, confirmation requires two AX-body reads at the original frame, the same WindowServer identity with the thumbnail outside the virtual display, and unchanged physical topology. The original error, including `CancellationError`, remains the error thrown to the caller. Teardown waits for any adoption in progress to finish.

- **Action**: `send(_ command:, to: AdoptedWindow, turn:, platform:?) async throws -> InputReceipt` stages when needed, prepares when the platform requests it, posts, restores, and attaches a `SeatObservation`. `sendSequence([InputCommand])` prepares once and restores once. `confirm(_ receipt:, _ effect: EffectConfirmation)` accepts `observed | absent | unknown` (unconfirmed means `unknown`; there is no timeout).
- **Errors**: `turnRequired`, `seatNotReady(state)`, `seatLimitReached`. `send` contains no queue; the only wait is in `acquire()`.
- **Issues**: critical seat issues (`processUnavailable`, `identityChanged`, `cursorInterference`, `ambiguousEffect`, `recoveryExhausted`) fail only that seat. `targetActivated` moves it to `waiting` without a deadline; it leaves that state on cancellation or when the application becomes inactive again, and an active application is never relocated. `windowUnavailable`, `geometryChanged`, and `snapshotChanged` move it to `recovering`; `windowStashed` reports a failed stage.
- **Recovery**: use WindowServer reads, not AX, every 250 ms; require 2 stable reads, allow 3 relocations and 5 s of unreadable-window time, then report `recoveryExhausted`. Wait for an in-flight Command up to its maximum duration; beyond that the Command is `unknown`. An `unknown` outcome on a recoverable issue produces `failed(.ambiguousEffect)` and is never replayed. `observed` closes the history; `absent` permits resending.
- **Observation**: every action carries a `SeatObservation` (frontmost application changed, Space changed, main display changed, maximum cursor distance, window order, target moved in front of the user's application, and cursor audit). The kit reports facts; it does not attribute them. (Ticket 10.)

### Input
`WindowReference(identity, frame)`; `InputLocation(screenPoint, windowPointFromTop, observedGeometry)`; `InputCommand: key(virtualKey, text, flags) | text(String) | insertText(String) | click(location, button: .left | .right) | drag(points, flags:) | scroll(location, deltaY)`. A drag is built like the current `pacedDrag` (an initial `mouseMoved`, 8 intermediate steps, realistic timing). Before building events, the driver rereads identity, frame, and scale. It translates every point only if dimensions, scale, and local layout are unchanged; resizing, a scale change, ambiguous cropping, or a different identity requires a new observation. After construction and routing, it rereads the same geometry immediately before the first post and refuses any change, without rebuilding or replaying. Window and connection come from the attested `WindowIdentity` and are written through `setIntegerValueField` to fields 51 and 52; the local point is written with `CGEventSetWindowLocation`. `SLEventRecordPointer` remains for the 0xF8 check and the gate's round trip. Legacy coordinates without an observation remain compilable but do not authorize live input. (Tickets 02, 05, 07, 09.)
`InputPlatform` (public, `Sendable` protocol): `preparation(for: InputCommand) -> .none | .internalAppKitState`, `preparationSettle(for:)` (**30 ms** by default: both families apply preparation within 20 ms in every measured case, plus half as margin; **150 ms** on Chromium only for `insertText`, where 30 ms succeeds seven times out of ten and 150 succeeds twelve out of twelve), `dragPacing`, and `decorate(_ event:, for:)` with an empty default. `AppKitPlatform` never prepares. `ChromiumPlatform` prepares left `click`, `drag`, and `insertText`; keyboard, text, scroll, and **right click** pass through without preparation. Preparation is harmful for right click because restoration posts a deactivation that menu tracking reads as an application change and dismantles the contextual menu at 440 ms. This also applies to Electron and CEF. `.universal` is `ChromiumPlatform` and is the default for `adopt`. Preparation consists of two `SLPSPostEventRecordTo` records (activation and key-window state in the target process only), with restoration guaranteed even on error. If preparation fails, no event is sent (`InputFailure.preparationFailed(code)`). `InputReceipt(eventCount, route, preparation, timing, observation, unvalidatedBuild)` is structured and contains no prose. (Ticket 11.)

### Capture and Monitor
`SeatFrame: Sendable { surface: IOSurface, pixelBuffer: CVPixelBuffer (BGRA), presentationTime, receivedAt, displayGeneration, source, geometry, pixelSize, makeCGImage() }`; `source` distinguishes the display, an attested window, and an unverified legacy Window ID. For each sample, `geometry` retains `screenRect`, `contentRect` in surface points, `scaleFactor`, `contentScale`, pixel dimensions, and the observer's local version; it is not an atomic WindowServer generation. Only a complete, attested window frame without shadow or clipping and with uniform mapping can produce coordinates. A receiver retains at most one frame (`queueDepth` 3 pool). The Monitor path retains the IOSurface through `CALayer.contents`, while `makeCGImage()` deliberately creates a stable copy. Two streams expose explicit `start(configuration:)`/`stop()` and `frames: AsyncStream<SeatFrame>` with `bufferingNewest(1)`: `SeatHost.monitor` (display filter, for the human) and `AgentSeat.capture` (window filter, for observation). The kit is the sole owner. Window sources are attested before and after `SCShareableContent`, compared with the PID published by SCK, and reread for every frame using already-cached symbols and gates. A mismatch publishes `.failed(.windowIdentityChanged)` and stops that exact stream without pretending Apple issued a callback. `AgentSeat.capture.still(timeout: 2 s)` takes a one-shot image of the adopted window with `SCScreenshotManager` and reports `CaptureFailure.timedOut` at the deadline. Before/after diffing lives in `SeatCore.FrameDifference`; `capturePair` is not API. `MonitorConfiguration(targetFrameRate: 30 | 60 | 120, output: .backing | .fixed(size))` defaults to 60 and backing output. The IOSurface pipeline is `IOSurface → CALayer.contents` (ticket 03). Quality degrades automatically from frame rate to resolution based on coalescence rate (primary) and heartbeat CPU (secondary), publishes `monitorQualityChanged`, and is exposed through `Monitor.quality`. 120 is allowed only with a 120 `refreshRate` and must be validated with 120 Hz content. The CPU value passed to the policy is the share **attributable to Monitor**, not total process CPU, because the 8% budget is net. In phase 6, feeding the total to the benchmark degraded a Monitor that cost 3% net because the captured scene itself cost 6.5%. A caller that cannot attribute a share passes no value. The kit provides `MonitorLayer: CALayer`; the consumer owns the `NSView`. (Tickets 05 and 12.)

### System
`BuildIdentity(osVersion: kern.osversion, productVersion, hardwareModel: hw.model)`; one `SymbolTable` resolution per facility; `RecordLayout` (0xF8, offsets with a round trip); `Ledger`; `FacilityReadiness: validated(build) | unvalidated(build | hardware) | unavailable(reason) | permissionMissing(kind)`; per-facility `allowUnvalidatedBuild`; and `Permissions.preflight/request(.postEvent | .screenRecording | .accessibility)`, which never prompts on its own. Loading rules: resolve at runtime, verify the build, validate size and layout, use one explicit route, observe the effect, fail closed, and never use a global fallback.

## 6. macOS version gate

(1) **Ledger** at `Sources/PrivateSymbols/Ledger/validated-builds.json`: one entry per build, with hardware as a list. Each primitive has `kind` (`symbol | class | selector | field | record | behavior`), `image`, `state` (`verified | limited | untested`), and `checks` (resolution, record length, offset round trip, effect). The per-facility verdict is **derived**. The ledger also records fragile public-API behavior (`CGDisplayIsOnline` returning `0xFFFFFFFF` for a removed display, actual `SCStreamConfiguration` defaults, releasing `CGVirtualDisplay` removing the display, and a globally framed window restored to the main display). Rejected primitives go in `docs/SpiLedger.md`. (2) **Compatibility suite** (`make compat-report`), with five steps per primitive: resolution, ABI shape, cross-validation (fields 51 and 52 against 0x3C and 0x40, `CGEventSetWindowLocation` against 0x20 and 0x28, and `SLSGetWindowOwner` on the process's own window), and the Live effect (display created and removed, tap installed, per-platform fixture matrix, stream with a `complete` frame, and `still`). It writes `docs/compatibility/Build<build>.md` with differences from the previous build and a JSON draft beside it. `verified` requires every step. (3) **Runtime readiness**: self-checks 1-3 always run when the facility starts. `validated` requires agreement between the ledger and self-checks. A failed self-check produces `unavailable` even when the ledger is favorable. A build or hardware outside the ledger produces `unvalidated(build | hardware)` and may act after runtime checks and permissions pass, with the unvalidated mark on Receipts and events (ADR 0015). `allowUnvalidatedBuild` remains source-compatible but no longer changes eligibility. Promotion is human-only through `make promote-build BUILD=…`, never automatic and never allowed for `inconclusive`. (Tickets 07, 08, and 14.)

## 7. Concurrency

Default isolation is defined per target (section 2). `InputDriver` is an `actor`. **`VirtualDisplay` is instead a `@MainActor` class with no internal waits** (ADR 0007, measured in phase 4): a virtual display advances only while `NSApplication` pumps events. A blocking wait holds the thread that should pump them, while an `async` wait returns the thread to the concurrency runtime, which under an `async main` terminates the process halfway through the run. The caller owns the lifecycle: the kit exposes predicates, and the caller queries them while running its own event pump. The fence runs on a dedicated `Thread` with its own `.userInteractive` run loop, and its callback has no external synchronous dependencies or allocations. Frame delivery occurs off-main; layer application occurs on-main. `SeatHost`, `AgentSeat`, and `NSScreen` registration are main-actor isolated. Pure types are `nonisolated` and `Sendable`. Role protocols in `facility` modules are declared `nonisolated` (ticket 06).

## 8. Tests and budgets

Three tiers: Unit (`swift test`, pure, parallel), Host (`AGENTSEAT_HOST_TESTS=1`, TCC and displays, `.serialized`), and Live (`AGENTSEAT_LIVE_TESTS=1`, fixture and reader, the ticket 02 matrix for every supplied `InputPlatform`, and `probe-page.html` under `Tests/Fixtures`). `SeatBench` produces the Reix JSON schema with complete provenance, a baseline per build-hardware pair, and budgets as Swift constants. Measurements use `mach_absolute_time`, the `malloc_logger` hook, and `proc_pid_rusage` with converted ticks. Every measurement subtracts a control; footprint is HWM-after minus HWM-before (tickets 05 and 13).

| What | Budget |
|---|---|
| fence callback (idle, anchor, audit) | 0 allocations; p99 ≤ 50 µs; never above 1 ms |
| click `send` (excluding the preparation wait) | attributable p95 ≤ 850 µs, never above 1 ms. The coordinated path reads and validates identity, geometry, and scale twice. On `26A428` / `Mac16,1`, three release runs measured 443.250, 403.917, and 410.458 µs, with a 410.458 µs median; the budget is rounded above 2 × the median. Identity must leave 0 residual kit allocations after a control measured with the same two `GetProcessPID` SDK calls; raw allocations for identity, control, geometry, and events remain reported. **Historical phase 5, before the two geometry reads**: attributable p95 was below control variance and the limit was 10 µs; that baseline is not comparable with the current coordinated path. |
| `makeEvents` / preparation | ≤ 6 allocations and ≤ 5 µs / **500 µs p95**: 100 µs was an unmeasured estimate, and one preparation cycle makes four WindowServer round trips (133-147 µs p50, 213-250 µs p95, phase 5). Preparation allocations occur inside `SLPSPostEventRecordTo` and are not attributable to the kit. |
| idle seat (display, fence, heartbeat) | median CPU ≤ 0.1%, p95 ≤ 1% over ≥ 5 min; wakeups ≤ 5/s; attributable footprint ≤ 4 MB |
| 1920×1080 monitor at 30 and 60 fps | net CPU ≤ 8%; p95 latency ≤ 2 ms; ≤ 12 MB net; coalescence ≤ 1%; provisional 120 fps ≤ 12% |
| display setup / removal | ≤ 800 ms p95 without settle / ≤ 200 ms p95 |

Regression rules: a budget violation fails; more than 10% above baseline for p95 latency or mean CPU/footprint fails; latency uses the median of 3 runs; high load is `inconclusive`; the first run on new build-hardware is `no-baseline`, never pass. Private primitives have three test levels: unit tests for layouts and the symbol table, host tests for resolution and round trips, and live tests for effects.
